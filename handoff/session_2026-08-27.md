## Decisions Made

- **`DemoStage`'s `.stage { min-height: ... }` fallback now has a documented, reusable opt-out pattern**: a CSS custom property (`--stage-min-height`) that any component guaranteeing a definite height (currently only `PhoneFrame`) can set to `0px` to disable the fallback locally, without deleting it globally (it's still load-bearing for a different, desktop scenario). Any future component embedding `DemoStage` with a definite-height guarantee should use this same channel rather than fighting the fallback another way.
- **Fan/collage sizing should derive from a single custom property (e.g. `--fan-h`) rather than hand-tuned `min-height` values** — this session found that a hand-tuned value from one round (`mobile_fit_plan.md`'s BookingSite `min-height: 210px`) silently went stale and had to be deleted when a later round (`mobile_polish_plan.md`) needed the fan's size to structurally track its container. Prefer the derived-property pattern for any future fan/collage work.
- **`.fill > .stack { flex: 1 1 auto; min-height: 0 }` is now the established pattern** for making a section's text block a flex-filler (content flush at the top, visual element — photo, fan, phone — floating in the remaining space) as an alternative to `justify-content: center`'s "split the slack evenly" behavior, which reads as "dead space above the heading" when a section's content doesn't nearly fill its box. Reuse this pattern; don't reach for `justify-content: center` on a section whose content is much shorter than its box.
- **Positional CSS selectors on mobile IA are now used deliberately** (`.card:not(:first-of-type)` for nav-clearance reclaim) but are explicitly flagged in code comments as depending on two separate facts staying true (DOM order in `page.tsx`, CSS `order` in `globals.css`) — both were independently re-verified by two different reviewer passes this session before being relied upon. Future changes to section DOM order or the mobile `order` block should re-check this dependency.
- **This session's overall pattern (established over the last several sessions) continued to work well**: brief `planner` with the orchestrator's own hypothesis/diagnosis attempt included explicitly, ask it to verify/refute/refine rather than trust blindly — in every round today the planner found either a stronger root cause (DemoStage's `min-height` regression) or corrected the magnitude of the orchestrator's own arithmetic (item 1's clipping was 5× larger than hand-calculated). Keep doing this.
